# Sion 主动决策：偏好反馈与策略演进

## 目标与边界

Sion 优化的是“在什么上下文下，是否应该主动、以及选择哪一类动作”，不是训练或微调底层大模型。LLM 负责把已选动作表达成自然语言；安全门控、决策记录和偏好策略必须保持可解释、可审计。

当前线上策略版本为 `rules-v1-audit`：规则评分与硬门控仍是主策略，显式反馈以“时段 × 工作状态”的上下文桶参与评分；同动作在当前上下文积累至少 3 个显式样本后使用局部偏好，否则回退到全局偏好。它不把未回复、任意用户聊天或 LLM 推测直接当奖励。

## 决策审计链路

```text
特征提取 → Drive × Action 评分 → 夜间/配额/间隔硬门控 → 投递
                                               │
                                               ▼
 proactive_decisions: decision_id、特征快照、候选动作、分数、策略版本、结果
                                               │
                         用户显式按钮 / API ───┴──→ proactive_feedback
                                               │
                                               ▼
                    上下文样本 ≥3 时施加局部偏好；否则回退全局偏好
```

每次完成动作选择的决策机会都携带 `decision_id`，包括 `silent / blocked / failed / delivered / resolved`，因而离线评估不会只看到已投递的幸存者样本。Dashboard 将反馈拆分为“有帮助 / 内容无关 / 时机不对 / 表达不适 / 稍后 / 别再提醒”，后端保留具体反馈类型。普通聊天不隐式结算任何决策，以避免将“用户另起话题”误判为接受。

如果投递后 15 分钟内出现下一条用户消息，系统会在 `proactive_replies` 中记录 `next_user_message` 候选归因，置信度为 0.5。该信号只用于分析候选回复率，不进入策略奖励。

每次反馈请求都有独立 `event_id`：同一请求重试只处理一次；用户之后修改选择时，新事件保留在追加审计表中，但只有 `proactive_feedback_current` 中的当前值进入统计，避免重试和改选重复计权。

`snooze` 会写入一小时的持久化全局暂停，`stop` 和主动模式的 `off` 会写入持久化静音；应用重启后仍生效。用户显式选择 normal/frequent/focus 时才会清除该全局控制。

## 为什么不把当前算法称为 DPO

DPO 需要同一上下文中的 chosen/rejected 偏好对。主动消息通常只有一次投递和稀疏、延迟的人类反馈，不具备这个数据条件。旧的动作权重更新原型不会在运行时修改实际评分器，故不应作为已上线学习能力描述。

当前使用显式奖励的平滑偏置，是为了以极低风险验证数据闭环；它只会微调动作排序，不能覆盖硬约束。

## Contextual Bandit 影子策略

项目已实现 `contextual-bandit-v1-shadow` 候选策略，但它不接管投递。它对显式反馈做 Beta(1,1) 收缩，加入有上限的不确定性探索项，上下文样本不足时回退到全局统计。它只对可交互动作排序，不给 `silence` 伪造奖励，“是否打扰”仍由规则和硬门控决定。

影子推荐、分数、是否与当前策略分歧、样本数和晋级就绪状态均写入决策快照。默认数据门槛是总显式反馈不少于 50，且至少 3 个动作各有 5 个样本。达到门槛仅代表可以开始评审，不会自动上线。

完整晋级路径：

1. 将时间段、应用类别、工作时长、距离上次主动消息、近期显式反馈等归一化为固定版本的上下文特征；
2. 对关怀、提醒、闲聊等低维可交互动作估计预期效用与不确定性；
3. 仅在每日探索预算内做低风险探索，夜间、专注模式和用户边界仍由硬门控处理；
4. 使用“影子动作=实际动作”样本上的匹配回放奖励、按动作/时段分桶的负反馈率和策略分歧率做初步离线评估。旧策略为确定性打分且没有记录 propensity，因此不对未匹配动作声称无偏的反事实效果。

## 可复现接口

```text
POST /api/v1/proactive/feedback
{
  "event_id": "client-generated-unique-id",
  "decision_id": "decision-...",
  "kind": "helpful|irrelevant|bad_timing|wrong_tone|snooze|stop",
  "note": "optional"
}
```

数据库表 `proactive_decisions`、`proactive_feedback`、`proactive_feedback_current`、`proactive_feedback_requests`、`proactive_replies` 和 `proactive_controls` 位于 Sion SQLite 数据目录，可用于回看任意一次主动行为的“当时为什么这样选、是否被门控、用户如何反馈、当前有效反馈是什么”。

`GET /api/v1/proactive/evaluation?days=30` 返回决策机会、投递/拦截/静默/失败数、显式反馈率、负反馈率、候选回复率、影子策略分歧率与匹配回放奖励。Dashboard 会展示这些指标，并明确区分“用户回了消息”和“用户给了正反馈”。

Dashboard 的“主动系统”页展示最近 8 条决策审计记录（动作、策略版本、内容、结算状态）；完整特征快照和候选动作保留在 SQLite 中，避免在界面上暴露无关的原始上下文。
